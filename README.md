# 騎士與龍 IV 自動練等與角色重抽

透過 Mac 的「iPhone 鏡像」操作《騎士與龍 IV》，協助你重複挑戰已選好的關卡，或在自訂創角頁尋找符合目標的角色。

| 想做的事 | 使用功能 |
| --- | --- |
| 重複打同一關、處理結算並再次出發 | [自動練等](#自動練等) |
| 重抽角色，直到總能力值達到指定門檻 | [角色重抽](#角色重抽) |

目前尚未發佈正式版本，需先在自己的 Mac 建立程式，再透過終端機啟動。第一次使用請先完成以下準備。

## 第一次使用

### 1. 準備環境

- Mac 使用 macOS 15 或更新版本，且能正常連線並操作「iPhone 鏡像」。
- iPhone 已安裝《騎士與龍 IV》，並能在鏡像視窗中進入遊戲。
- 目前以繁體中文遊戲畫面辨識；其他語言或不同介面配置可能無法使用。
- 安裝完整版 Xcode，放在 `/Applications/Xcode.app`，首次開啟並完成安裝。需要支援 Swift 6.2 或更新版本的 Xcode。

開啟「終端機」，輸入 `cd` 加一個空格，再把專案資料夾從 Finder 拖入終端機，按下 Enter。以下指令都在這個資料夾中執行。

### 2. 建立程式

```sh
zsh Scripts/build-app.sh
```

完成後會產生 `.build/Mirror Probe.app`。已有這個程式、且沒有更新專案時，可以略過此步。

### 3. 開啟必要權限

先開啟 iPhone 鏡像並連上手機，再執行：

```sh
open -g -W -n ".build/Mirror Probe.app" --args doctor --request-permissions \
  --output "$PWD/logs/permissions.json"
```

依提示到「系統設定 → 隱私權與安全性」，為 **Mirror Probe** 開啟：

- **螢幕錄製**：讓程式看見遊戲畫面。
- **輔助使用**：讓程式操作鏡像中的按鈕。

這個檢查不會按下遊戲按鈕。完成授權後，再執行一次上述檢查；結果會存到 `logs/permissions.json`。其中 `screenCapturePermission` 與 `postEventPermission` 都應為 `granted`。

如果專案放在桌面，macOS 也可能要求桌面資料夾存取權。先處理完權限視窗，再開始使用。更新並重新建立程式後，可能需要重新授權。

## 自動練等

### 開始執行

1. 在遊戲中啟用預設的「全部自動」。工具會沿用這個設定，不會替你切換。
2. 手動進入要重複挑戰的關卡，停在戰鬥開始提示或戰鬥畫面。
3. 保持一個 iPhone 鏡像視窗開啟，執行：

```sh
./auto-level.zsh --max-cycles 10 --max-minutes 20 --wait
```

這個範例會在完成 10 場或執行 20 分鐘時停止，以先到者為準。啟動時正在進行的那一場也會計入場次。`--wait` 會讓終端機等待結束，並顯示完成場次、停止原因與時間統計。

結束摘要會顯示開始／結束時間、總耗時、每個 cycle 的平均／中位數／最快／最慢／最近耗時、最後完成後的經過時間，以及每小時完成數。同樣的數據也會寫入 `run-report.json` 的 `timing` 欄位（schema 6），不加 `--wait` 時仍會記錄。

- 第一個 cycle 從程式開始執行量到首次辨識到結算，其後從上次結算量到下次結算，包含中間領獎、重新出發與等待的時間。成功與失敗都依既有場次規則計入。
- **第一個 cycle 可能已進行到一半**，因此每個 cycle 的時間統計代表本次程式實際觀測到的耗時，並非完整戰鬥的耗時。
- 平均耗時 = 已完成 cycles 的合計耗時 ÷ 完成數；最後完成後直到停止的區段另外顯示，不加入這個平均。每小時完成數則使用整段執行時間，反映整體效率。
- 中位數（`medianCycleSeconds`）把同一批已完成 cycles 的耗時排序，取中央值；偶數筆取中央兩筆的平均，較不受少數特別快或特別慢的場次影響。報告也保留各場耗時 `cycleDurationsSeconds`，供核對統計。
- 尚未完成任何 cycle 時，其平均／中位數／最快／最慢／最近耗時顯示「尚無資料」，JSON 為 `null`；舊版報告缺少 `timing` 或中位數時不推算數據。時間長度使用單調時鐘，避免調整系統日期影響計算。

工具會處理支援的遊戲提示，在結算頁選取「重複進行此任務」並再次出發。對於支援的中央對話框，只有一個按鈕時會按下它；有兩個按鈕時會選上方，可能包含領獎、招募等選擇。確認戰鬥卡住時，可能嘗試撤退後重新挑戰；工具不檢查護符使用狀態。

同一場戰鬥已被確認後，若「跳過／全部自動」持續辨識失敗，但每次擷取仍能辨識「撤退」，工具會先等待 **30 秒**；屆時重新擷取並確認撤退按鈕後，會撤退並接續確認、結算及重複任務流程。正常辨識恢復時會取消等待。若撤退按鈕也無法辨識、鏡像中斷或視窗／輸入狀態改變，便不會沿用這次撤退資格。

### 常用設定

| 指令參數 | 用途 | 省略時 |
| --- | --- | --- |
| `--max-cycles 50` | 完成 50 場後停止 | 不限制場次 |
| `--max-minutes 60` | 執行 60 分鐘後停止 | 不限制時間 |
| `--wait` | 等待結束並顯示結果 | 啟動後立即回到終端機，程式繼續執行 |
| `--capture-level info` | 額外保存操作前後畫面，方便排查問題 | 正常停止不留圖；錯誤或安全停止最多保留最後 8 張 |

**直接執行 `./auto-level.zsh` 沒有場次或時間上限。** 第一次使用可以先採用上方有上限的範例。

想讓 Mac 在這段時間保持喚醒，可使用：

```sh
caffeinate -di ./auto-level.zsh --max-minutes 60 --wait
```

### 錯誤後自動重啟

已有建置好的 App 時，可以改用外層重啟器，不需要重新編譯或修改 macOS 設定：

```sh
./auto-level-restart.zsh --max-restarts 3 --restart-delay 10 --max-minutes 60
```

- 重啟器會在終端機等待。視窗位置／尺寸變動、短暫無法取得視窗或擷取失敗，且本次程序已結束並留下完整報告時，才會等待後重啟；預設最多額外重啟 3 次、每次等 10 秒。
- 每次重啟使用獨立紀錄目錄、重新辨識畫面。`supervisor-report.json` 保存整輪摘要，`attempt-001` 等目錄保存各次報告與截圖。
- 正常完成、手動停止、背包滿、權限缺失、辨識不確定或無完整結束報告時，會直接結束，不再重啟。
- 可按 **Ctrl-C**，或使用啟動時印出的整輪 `STOP` 指令。重啟器會通知目前 App 停止，並取消後續重啟；若 App 未及時結束，會保留 STOP 並明確回報。
- `--max-minutes` 套用整輪，包含等待重啟的時間；到期會要求 App 停止。`--max-cycles` 採各次報告合計，重啟後若再次看到同一結算頁，可能重複計入並提早達到上限。
- `--window-id`、`--capture-level`、`--dry-run` 也適用；`--output-dir` 指定的是整輪的新目錄。

### 執行時的視窗操作

- 保持鏡像開啟且可擷取。切換外接顯示器、移動或調整視窗後，請等視窗穩定；不要持續拖動或最小化。
- 鏡像視窗的大小可以用「顯示方式 > 放大／縮小」調整，自動練等支援各個縮放級距（同一台 Mac 從最小到最大）。工具會自動找出鏡像視窗固定的白色邊框，把手機畫面對齊到校準用的比例後再辨識，點擊位置也會換算回實際視窗。請在啟動前調好大小；執行中改變大小仍會觸發上一點的暫停與重新確認。
- 其他一般視窗可以蓋住鏡像。需要點擊時，工具會暫時把鏡像切到前景，之後嘗試切回原本的程式。
- 這段切換會使用共用滑鼠與輸入焦點，同時打字或操作滑鼠可能受影響。
- 視窗短暫消失或位置／尺寸改變時，工具會暫停操作，在最多 4 次查詢、5 秒內等待恢復。同一視窗的新位置與尺寸需間隔至少 1 秒、連續兩次保持一致，才會重新擷取畫面、辨識按鈕並計算點擊位置。原有操作或執行期限可能讓等待提早結束。
- 遇到背包滿、持續無法辨識的畫面、視窗持續改變或無法安全點擊等情況，工具會停止。先處理遊戲畫面，再重新啟動。

## 角色重抽

### 開始執行

1. 在 iPhone 鏡像中開啟遊戲的「自訂創角」頁。
2. 執行下方指令，並讓鏡像維持在前景：

```sh
./reroll-character.zsh
```

預設尋找 **`total ≥ 90`** 的角色，最多重抽 **500 次**或執行 **10 分鐘**，以先到者為準。

達到門檻後，工具會停止並保留目前角色，**不會按下「決定」**。請自行查看角色內容，再決定是否採用。如果數值無法確認或畫面不穩定，工具也會停止，此時不代表已達標。

### 調整目標與上限

例如：尋找總能力值至少 95 的角色，最多重抽 1,000 次或執行 20 分鐘：

```sh
./reroll-character.zsh --minimum-total 95 --max-rerolls 1000 --max-minutes 20
```

| 指令參數 | 可設定範圍 | 預設值 |
| --- | --- | --- |
| `--minimum-total` | 90–100 | 90 |
| `--max-rerolls` | 1–5,000 次 | 500 次 |
| `--max-minutes` | 1–60 分鐘 | 10 分鐘 |

執行期間請保持鏡像在前景，不要切換程式、移動或調整視窗大小。角色重抽會停留在鏡像中，不會自動切回原本的程式。

## 如何停止

**兩種功能啟動時，都會印出本次執行專用的停止指令。** 複製那一整行，在另一個終端機分頁或視窗執行即可。它的形式如下，請使用畫面印出的實際路徑：

```text
touch /本次執行的資料夾/STOP
```

這會通知工具停止；請稍候，讓它完成目前的檢查與結果保存。停止工具不會暫停遊戲本身。

- **自動練等**：請使用上述停止指令。即使加上 `--wait`，單按 Ctrl-C 也可能只結束終端機的等待，不能據此確認工具已停止。
- **角色重抽**：也可以在啟動它的終端機按 Ctrl-C，啟動器會建立停止檔並等待收尾。

停止後若要繼續，確認遊戲停在適合的畫面，再重新執行啟動指令。每次都會建立新的紀錄與停止路徑。

## 常見問題

| 遇到的情況 | 處理方式 |
| --- | --- |
| 找不到 `Mirror Probe.app` | 在專案資料夾執行 `zsh Scripts/build-app.sh`。 |
| 建立程式時找不到 Xcode 或版本不支援 | 確認安裝的是完整版 Xcode、路徑為 `/Applications/Xcode.app`，並已完成首次開啟的安裝步驟。 |
| 提示缺少螢幕錄製或輔助使用權限 | 到系統設定為 Mirror Probe 開啟權限，再執行第一次使用的檢查指令。重新建立程式後也可能需要重新授權。 |
| 找不到鏡像視窗 | 確認手機已連線，鏡像沒有最小化，且位於目前的桌面空間。 |
| 提示有多個鏡像視窗 | 先關閉其他鏡像視窗，只保留要操作的一個。 |
| 提示同一視窗已有程序執行 | 先使用前一次啟動時印出的停止指令，等它結束後再重開。 |
| 自動練等沒有繼續戰鬥 | 檢查遊戲的「全部自動」設定、背包空間，以及是否停在工具不支援的畫面。 |
| 鏡像視窗縮小後畫面持續辨識失敗 | 錯誤紀錄會印出 `mirrorContentLayout:`，可確認邊框是否被找到。先用「顯示方式 > 實際大小」或放大後重試；仍失敗時保留 `final.png` 回報，小尺寸下部分頁面可能需要補充辨識樣本。 |
| 滑鼠或程式焦點被切走 | 自動操作會使用共用滑鼠與焦點。需要專心使用 Mac 時，先停止工具。 |
| 重抽在未達標時停止 | 可能已達次數／時間上限，或無法確認畫面與數值。查看終端機訊息及遊戲畫面，再決定是否重新執行。 |
| 提示簽章驗證失敗 | 重新執行 `zsh Scripts/build-app.sh`，再確認權限。 |

## 查看紀錄與回報問題

啟動時會顯示本次執行的紀錄位置，預設放在專案的 `logs/`。遇到問題時，請保留：

- 終端機顯示的錯誤訊息，以及你執行的指令。
- 本次的 `run-report.json` 與錯誤紀錄。自動練等的錯誤紀錄是執行資料夾旁的 `.stderr.log`；角色重抽則在執行資料夾內的 `stderr.log`。
- 本次留下的截圖（如果有）。自動練等出錯時可能有 `final.png`；角色重抽可能有 `final-candidate.png`，請同時附上報告以便確認截圖所代表的狀態。

確認所有執行都已停止、也不再需要排查問題後，可以清理 `logs/`。執行中請保留本次紀錄資料夾，讓停止指令與結果保存正常運作。
